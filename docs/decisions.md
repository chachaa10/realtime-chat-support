# Decisions

## Architecture

| # | Decision | Choice |
|---|---|---|
| 1 | Frontend framework | TanStack Router + Vite (SPA, no SSR) |
| 2 | Real-time transport | Socket.io via @nestjs/websockets + @nestjs/platform-socket.io |
| 3 | Repo structure | Turborepo + pnpm monorepo: apps/frontend, apps/backend, packages/shared, packages/database |
| 4 | Monorepo tool | Turborepo v2 with tasks key. turbo.json defines build, test, typecheck pipelines. lint/fmt run at root only. |
| 5 | Package manager | pnpm workspaces |
| 6 | Build tool (packages) | tsdown |

## Backend

| # | Decision | Choice |
|---|---|---|
| 7 | Runtime | Node.js (NestJS runs natively) |
| 8 | Framework | NestJS |
| 9 | Database | SQLite via better-sqlite3 driver |
| 10 | ORM | Drizzle ORM + @drizzle-orm/better-sqlite3 adapter |
| 11 | Auth | better-auth with Drizzle adapter. Email/password only. |
| 12 | Rate limiting | @nestjs/throttler: 100 req/min per-user, 500 req/min global ceiling. WS: 1 reconnect:sync/5s per socket, 10 connects/min per IP. |
| 13 | API response contract | Success: { data: T }, Error: { error: { code, message, errors? } }, Paginated: { data: T[], meta: { cursor } } |
| 14 | File storage | Abstracted behind FileStorage port/adapter. LocalFileStorage writes to uploads/. Swappable to S3. |
| 40 | Attachment flow | Two-level: ticket-level (at creation) + message-level (in chat). Two-step orphan-then-link: upload -> upload token -> link on form submit. Orphans cleaned after 1 hour. Age-based cleanup after 30 days. |

## Database

| # | Decision | Choice |
|---|---|---|
| 15 | IDs | SQLite auto-increment integer |
| 16 | Profiles | profiles table extends better-auth users with role field only. User name lives in better-auth users table. |
| 17 | Status enum | open, in_progress, resolved, cancelled. |
| 18 | State machine | open -> in_progress -> resolved (terminal). open -> cancelled (terminal). in_progress -> open (agent returns to queue). No reopen from resolved or cancelled. |
| 19 | Ticket Events | Every status transition recorded in ticket_events table. Created on ticket creation and every status change. |
| 20 | Labels | Predefined set seeded in database. No runtime management UI. Many-to-many with tickets via ticket_labels join table. |
| 21 | Migration approach | SQL files generated by drizzle-kit generate, run via runMigrations() entry point. |

## Domain Model

| # | Decision | Choice |
|---|---|---|
| 27 | User identity | better-auth owns the users table (name, email). App adds profiles table (id FK, role). Profile auto-created on registration via hook. |
| 28 | MSG-6 (pre-accept chat) | Dropped. Agent must accept ticket before seeing conversation or sending messages. |
| 29 | Internal agent notes | Skipped for P0. Agents coordinate out-of-band. |

## WebSocket Protocol

| # | Decision | Choice |
|---|---|---|
| 31 | WS scope | Real-time broadcasts only. All mutations go through HTTP endpoints. |
| 32 | WS events | ticket:new, ticket:accepted, ticket:resolved, ticket:cancelled, message:sent, file:uploaded, reconnect:sync |
| 33 | WS auth | JWT handshake. Room membership gated by ticket authorization. |
| 34 | WS error format | Same shape as HTTP errors (code, message, errors?) — no wrapping error key. Ack callbacks return undefined on success. |

## Notifications

| # | Decision | Choice |
|---|---|---|
| 41 | Notification delivery | Three channels: in-app notification feed (persisted to DB), browser tab title flash (unread count), in-app toast. All delivered via WebSocket when connected; persisted for retrieval on page load. |
| 42 | Notification triggers | Customer: ticket accepted, ticket returned to queue, ticket resolved. Agent: new ticket in queue, new message (if not viewing that ticket). |
| 43 | Notification read state | Auto-marked as read when user views the relevant ticket. Unread count drives tab title flash. No explicit "mark all read" for P0. |

## Cross-cutting

| # | Decision | Choice |
|---|---|---|

| 45 | Lint | oxlint |

| 48 | Code style | Co-located __tests__/ per feature. Factories + mocks in apps/backend/src/__tests__/helpers/. |

## Rejected Alternatives

| # | Rejected | Why |
|---|---|---|
| 49 | Bun as runtime | NestJS compatibility concerns. Node.js + tsx used instead. |
| 50 | ServeStaticModule for file serving | Security: need ticket membership check on every file access. Custom guarded endpoint instead. |
| 51 | WS mutation events | Duplicates HTTP endpoints. All CRUD through HTTP, WS for broadcast only. |
| 52 | GraphQL | Overkill for CRUD with real-time. REST + Socket.io is simpler. |
| 53 | Prisma | Drizzle chosen for better SQLite support and lighter footprint. |
